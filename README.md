# Automated Timetable Generation

A team coursework prototype using Python, Pandas, Excel and Flask. It is a Python-based constraint-satisfaction scheduling engine using a Greedy Algorithm across 24 weekly timeslots (6 days x 4 periods), dynamically eliminating instructor/classroom overlaps and generating personalized schedules through a Flask web interface. This is an educational archive, not a production scheduling or student-record system.

## Privacy-safe local demo

The original student/faculty spreadsheets are not included. `make_example_data.py` creates three tiny, entirely synthetic workbooks with demo courses, generic faculty names and fake student IDs. The fourth workbook, `Master_Timetable.xlsx`, is generated by the app as output. None of these generated files should be committed.

```bash
python -m venv .venv
# Activate .venv.
pip install -r requirements.txt
python make_example_data.py
python app.py
```

Open the local URL printed by Flask. Try demo student `1001` or `1002`. ID `8` opens the coursework's master-table view. This is a demo switch, NOT authentication. Do not expose the server to the internet or use real student records.

Run the example generator from a clean checkout. It refuses to overwrite existing workbooks. The app writes `Master_Timetable.xlsx` on startup. Generated input and output files are ignored by Git.

## Files

- `app.py`: original Flask scheduling prototype with minimal local-safety cleanup.
- `templates/index.html`: supplied demo interface with remote university branding/background removed.
- `make_example_data.py`: new, explicitly synthetic setup data generator added during portfolio cleanup.
- `timetable_experiments.ipynb`: output-free archive of the original experiments, not the recommended demo entry point. Some experiments expect additional original spreadsheet fields and interactive input, so are not guaranteed to run with the minimal demo tables.

## Algorithm

The implementation greedily places courses in faculty-available slots and caps each slot at two courses, eliminating instructor and classroom overlaps.

- Shared state is initialized by the script entry point, not an application factory; run `python app.py` for the demo rather than assuming a WSGI deployment works.

Do not use the prototype for real course allocation.
